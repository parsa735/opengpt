# OpenGPT

Local personal OpenAI-compatible API bridge that uses a ChatGPT Plus/Pro OAuth session and the Codex backend.

```text
Cursor / OpenCode
        |
 POST /v1/chat/completions  or  /v1/responses
        |
 localhost:5080  (opengpt)
        |
 ChatGPT OAuth + Codex
        |
 https://chatgpt.com/backend-api/codex/responses
```

> This is a local personal adapter. It is not a multi-user or hosted gateway.
> Using ChatGPT subscription credentials outside official clients may conflict with OpenAI terms — use at your own risk.

## Architecture and contributor guide

See [`AGENTS.md`](AGENTS.md) for the complete architecture, runtime flows, production class and service map, test map, configuration reference, invariants, and change-impact guidance for coding agents and maintainers.

## Requirements

- Java 21+
- Maven 3.9+
- ChatGPT Plus/Pro account

> Note: Uses Spring Boot **4.0** (current start.spring.io floor). PRD requested 3.x; behavior matches the PRD APIs.

## Run

```bash
mvn spring-boot:run
```

Or build a jar:

```bash
mvn -DskipTests package
java -jar target/opengpt-0.1.0-SNAPSHOT.jar
```

Server binds to `127.0.0.1:5080` only (OAuth callback still uses `127.0.0.1:1455`).

> Maven resolves dependencies from Maven Central via `.mvn/maven.config` (project settings). This bypasses a typical user-level Maven mirror that may not host Spring Boot 4; installation-wide Maven settings can still be merged.

## First-time auth

1. Open http://localhost:5080
2. Choose a login method:
   - **Login with browser** — ChatGPT OAuth returns to `http://localhost:1455/auth/callback` (Codex-registered redirect)
   - **Login with device code** — open `https://auth.openai.com/codex/device`, enter the one-time code, no local callback port required
3. Tokens are stored at `~/.opengpt/auth.json` (best-effort `0600` on POSIX filesystems)

For device code login, enable **Device code authorization** in ChatGPT → Settings → Security (or your workspace admin permissions). Codes expire after 15 minutes.

Do **not** change `openai.oauth.callback-url` away from port `1455` — OpenAI rejects other redirect URIs for this client id. `openai.oauth.callback-url` and `openai.oauth.callback-port` must also remain consistent with each other. Device-code token exchange uses OpenAI’s hosted `…/deviceauth/callback` redirect and does not use port `1455`.

## Client configuration

After login, open http://localhost:5080 and copy:

```text
Base URL:  http://localhost:5080/v1
API Key:   sk-cla-...   (generated by the adapter — use Copy)
```

### Cursor

1. Paste the **generated** API key into OpenAI API Key (not a random string like `test`).
2. Set Override OpenAI Base URL to `http://localhost:5080/v1`.

**Important:** Cursor often returns `Access to private networks is forbidden` for `localhost` base URLs because requests are proxied through Cursor’s cloud. If you see that error, the adapter console will show **no logs** — Cursor never reached you. Options:

- Prefer a local client that talks to localhost directly (for example, OpenCode).
- If a public HTTPS tunnel is unavoidable, require authentication/access control at the tunnel and expose only the `/v1/*` routes needed by the client. Do not publish the whole service without protection: `/`, `/auth/*`, and key regeneration are not protected by the adapter API-key filter, and the home page displays the generated key.

#### Reasoning effort

Cursor currently drops its reasoning-effort selector from requests sent through **Override OpenAI Base URL**. It can also canonicalize a selected GPT-looking alias such as `gpt-5.6-sol-low` to `gpt-5.6-sol` before the request reaches the adapter. The adapter cannot recover an effort value that is absent from both the model ID and request fields; bare GPT-5.6 models therefore keep the `xhigh` fallback.

For Cursor, manually add and select one of the deliberately non-GPT-looking `cla-*` aliases:

```text
cla-astra-low     cla-astra-medium    cla-astra-high
cla-astra-xhigh   cla-astra-max

cla-sol-low       cla-terra-low       cla-luna-low
cla-sol-medium    cla-terra-medium    cla-luna-medium
cla-sol-high      cla-terra-high      cla-luna-high
cla-sol-xhigh     cla-terra-xhigh     cla-luna-xhigh
```

For example, `cla-astra-high` is sent upstream as model `gpt-6-astra` with `reasoning.effort=high`, while `cla-sol-low` maps to `gpt-5.6-sol` with `reasoning.effort=low`. These aliases are advertised by `/v1/models`. Astra also supports the direct `gpt-6-astra-{low|medium|high|xhigh|max}` aliases and defaults to `high`; access still depends on the ChatGPT account's staged Astra entitlement. The older `gpt-5.6-*-{effort}` aliases remain supported for clients that preserve the full model ID, but they are not reliable through affected Cursor versions. Explicit `reasoning.effort`, `reasoning_effort`, `reasoningEffort`, and compatible `cursor_model_params` values also take precedence over model aliases and fallback.

The adapter also writes full, unredacted client and Codex traffic to `~/.opengpt/traffic.log`. This can include prompts, source code, tool arguments/results, images, local paths, and model output. Protect or remove this file before sharing diagnostics.

### OpenCode

Point the OpenAI provider base URL at `http://localhost:5080/v1` and use the generated API key.

## Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| GET | `/health` | Liveness |
| GET | `/` | Login UI |
| GET | `/auth/login` | Start browser OAuth |
| POST | `/auth/device/start` | Start Codex device-code login |
| POST | `/auth/device/poll` | Poll device-code approval / complete token exchange |
| GET | `/auth/callback` | Main-server OAuth callback fallback |
| GET | `/auth/status` | Authentication metadata |
| POST | `/auth/regenerate-key` | Replace the local client API key |
| GET | `/v1/models` | Model list |
| POST | `/v1/responses` | Prepared and proxied Responses SSE |
| POST | `/v1/chat/completions` | Streaming or aggregated Chat Completions |

## Implementation status

Implemented features include OAuth login/refresh, local API-key protection, model discovery, Responses SSE proxying, Chat Completions request/stream translation, multimodal image mapping and Cursor placeholder recovery, function/custom tools including `ApplyPatch`, encrypted reasoning continuity, usage translation, keepalives, and non-streaming text aggregation.

Hardening remains ongoing. Important current limitations and security boundaries are documented in [`AGENTS.md`](AGENTS.md), including non-streaming tool-call loss, always-on sensitive traffic logging, local-file image recovery, and the risks of publishing unauthenticated UI/auth routes.

## Tests

```bash
mvn test
```

`OpengptApplicationTests` currently runs without the test profile and can append an adapter-start marker to the real `~/.opengpt/traffic.log`. Other profile-based integration tests use fixed files under the system temporary directory.
